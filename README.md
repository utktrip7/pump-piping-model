# Pump-Piping System Simulator

Python/Streamlit tool that calculates pipe pressure drop, the operating point of a centrifugal pump in a piping system, and flow through Venturi and orifice meters. It is validated against my own fluid mechanics lab data and includes a small ML surrogate model.

**Live app:** (https://pump-piping-model-vv6glbjfmvv9hxtjnnt9u9.streamlit.app/)

## Features
- **Pump & system:** friction loss in straight pipe and fittings, pump curve fit, operating point (flow and head where the pump curve meets the system curve)
- **Meter calculator:** flow rate from a manometer reading for a Venturi or orifice meter
- **Lab validation:** discharge coefficient (Cd) vs Reynolds number from my own experiment, compared with textbook values
- **ML surrogate:** Random Forest that predicts the operating flow, shown next to the physics answer
- Input checks everywhere (bad inputs raise clear errors) and a pytest suite for every physics module

## Methods
| Part | Equation / method |
|---|---|
| Reynolds number | Re = ρvD / μ |
| Laminar friction factor (Re < 2300) | f = 64 / Re |
| Turbulent friction factor (Re > 4000) | Swamee-Jain: f = 0.25 / [log10(ε/(3.7D) + 5.74/Re^0.9)]² |
| Transitional (2300 to 4000) | Straight-line interpolation between the two (approximation, a warning is issued) |
| Straight pipe | Darcy-Weisbach: h = f (L/D) v² / 2g |
| Fittings | h = K v² / 2g, K values summed for fittings in series |
| Pump curve | Quadratic fit H = a + bQ + cQ² |
| System curve | H = H_static + ΔP_total(Q) / ρg |
| Operating point | Root of (pump head − system head), scipy brentq |
| Meters | Q = Cd · A · √(2ΔP / (ρ(1 − β⁴))), ΔP = (ρ_manometer − ρ) g h |

## Lab validation
Experiment: flow measurement with Venturi, orifice and rotameter (pipe 25.4 mm, Venturi throat 14.67 mm, orifice 14.6 mm, CCl4 manometer, water, viscosity 0.901 cP). Actual flow from collected volume and time. 16 readings from my own sheet and a second group's sheet (`data/lab_data.csv`).

![Cd vs Re](docs/cd_vs_re_validation.png)

| Meter | Readings used | Mean Cd | Textbook Cd | Error |
|---|---|---|---|---|
| Venturi | 2 | 0.837 | about 0.98 | -14.6% |
| Orifice | 2 | 0.903 | about 0.61 | +48.1% |

**Exclusion rule (applied in code):** a reading is excluded if its collected volume conflicts with the rotameter setting (2 readings), or if Cd ≥ 1, which is physically impossible (10 readings). 12 of 16 readings were excluded; all are shown in the app.

**Honest assessment:** the validation is weak. Most readings gave Cd above 1, meaning the measured pressure difference was too small for the flow. Likely causes: air bubbles in the manometer lines, short collection times (about 5 s) and manometer fluctuation. Excluding only readings that are too high biases the means downward, so they are not unbiased estimates. The orifice result is far from 0.61 and should not be read as validated. Textbook Cd values apply at high Reynolds numbers, while the lab ran at Re of about 1,000 to 12,000. A repeat run with longer collection times and bled manometer lines is needed.

## ML surrogate (experiment)
A Random Forest was trained on 100,000 simulated systems (water, fixed pump curve). Inputs: static head, pipe length, diameter, roughness, number of 90° elbows, number of globe valves. Target: operating flow. The data is generated by the physics code (`scripts/generate_data.py`, fixed seed, so it is reproducible). The CSV is not committed; run the script to create it.

| Test | Linear regression | Random Forest |
|---|---|---|
| R² (random 20% hold-out) | 0.928 | 0.998 |
| MAE (hold-out) | 0.088 L/s | 0.016 L/s |
| Mean % error (hold-out) | not measured | 1.5% (95th percentile 4.7%, worst 17.3%) |
| Trained on pipes under 40 mm, tested on 40 mm and above: mean % error | 16.3% (worst 76.7%) | 7.2% (worst 17.5%) |

- **Most important inputs:** diameter (0.63) and static head (0.28), consistent with the physics.
- **Speed:** predicting 19,693 cases took 0.11 s, about 10x faster per case than the physics code. The physics already solves 100,000 cases in about 7 s, so the surrogate is not needed here.
- **Limitation:** accuracy drops outside the sampled input ranges (7.2% error on unseen pipe sizes vs 1.5% inside the range). The physics model has no such limit.
- The app's surrogate tab trains on 20,000 cases at startup, so its error is slightly higher than the 100,000-case results above.

## Assumptions and limitations
- Incompressible, single-phase, steady flow; single pipe diameter
- K values are typical textbook values and vary by source [cite your textbook]
- The transitional-range friction factor is an interpolation, not a measured value
- The pump curve is a quadratic fit and is only valid within the range of the data
- Static head is entered by the user; no pipe elevation profile
- The surrogate only covers: static head 0 to 15 m, length 5 to 100 m, diameter 20 to 50 mm, roughness 0.0015 to 0.2 mm, 0 to 10 elbows, 0 to 5 globe valves

## Project structure
```
app.py                        Streamlit app (4 tabs)
requirements.txt
src/
  friction.py                 Reynolds number, flow regime, friction factors
  pipe.py                     Pipe and fitting losses, total pressure drop
  pump.py                     Pump curve fit, system curve, operating point
  meters.py                   Venturi and orifice calculations, manometer
  validation.py               Lab data processing (Cd, Re, error table)
  surrogate.py                Data generation and Random Forest for the app
tests/
  test_friction.py  test_pipe.py  test_pump.py  test_meters.py
scripts/
  plot_operating_point.py     Pump and system curve plot
  plot_validation.py          Cd vs Re plot and error table
  generate_data.py            Simulated dataset for the surrogate
  train_surrogate.py          Linear vs Random Forest, error and speed
  extrapolation_tests.py      Surrogate tested on unseen pipe sizes
data/
  lab_data.csv                16 lab readings
docs/                         Figures used in this README
```
